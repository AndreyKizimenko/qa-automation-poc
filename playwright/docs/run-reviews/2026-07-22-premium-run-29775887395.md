## Root cause

A classic image-vs-package drift:

- `playwright/package.json` declares `"@playwright/test": "^1.61.1"`, so `npm ci` installs
  the 1.61.1 test runner, which expects the `-1228` headless-shell build.
- At the run's commit `a8ee654`, `.github/workflows/playwright-premium.yml` still pinned the
  container to `mcr.microsoft.com/playwright:v1.59.1-noble`
  (confirmed: `git show a8ee654:.github/workflows/playwright-premium.yml` → `v1.59.1-noble`).
- The 1.59.1 image doesn't carry the browser build 1.61.1 wants, and the workflow deliberately
  skips `playwright install` ("Browsers are pre-installed in the image"), so nothing fetches
  the missing binary at runtime → launch fails.
