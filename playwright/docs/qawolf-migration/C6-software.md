### Role-model / infra gaps
- Static users already cover `global-admin` / `global-maintainer` / `global-observer` → all manage-automations access flows map cleanly; no missing role user here.
- **fleetctl `trigger --name vulnerabilities`** scaffolding (flows 7, 8) — our suite does not freshen vuln data via CLI; assume ambient vuln data and drop the scaffold.
- **Host-dependent** (flag): flow 25 needs a live enrolled RPM/Fedora host + gitops policy; flow 27 needs a live Unassigned (no-team) Linux host with the uploaded installer. Aligns with the host-dependent roadmap in memory.
- **Team-create / naming rework**: flows reference teams outside our gitops model — "Virtual Machines" (20, 21, 25), "QAW Scripts" (24), "Ducks/Geese/Pigeons/Swans/Turkeys" (3, 28). Rework to Workstations / Unassigned / All fleets.
- **Org-level state mutation**: vulnerability-automations spec (16, 17) flips a GLOBAL webhook config, not team-scoped content — needs explicit save/restore so it doesn't leak into other specs (cleanup-teardown wipes team content, not app config).
