# 18 — Class-based locator verification (page objects vs. React source)

Every `locator('.…')` under `playwright/pages/**/*.ts` was checked against the component
that emits the class in `~/repositories/fleet/frontend/`. Nothing was modified.

## Summary

- **102 distinct class-based locator strings** across 43 of the 75 page/component objects, resolved to 56 table
  rows: **16 `replace`**, **32 `keep`**, **54 selectors `sanctioned`** (collapsed to 8 category rows),
  **0 `unverified`**.
- Top 3 replacements: **(1)** `.Select-option` → `getByRole('option', { name })` — react-select **v1**
  *does* emit `role="option"` + `aria-label`, unlike v5; **(2)** `.selected-teams-form__team-item` →
  `getByRole('listitem').filter({ has: getByRole('checkbox', { name, exact: true }) })`, which also
  fixes a live substring-match bug; **(3)** `.compatible-platform` → `getByTestId('check-icon')`
  (Fleet's `Icon` stamps `data-testid="{name}-icon"` on every icon).
- **Refuted the brief's dropdown-option hypothesis.** `data-testid="dropdown-option"` is emitted by
  `DropdownWrapper` **only**. `ActionsDropdown`, `TeamsDropdown` and `LabelFilterSelect` are separate
  react-select-v5 call sites with no testid, and react-select **5.4.0 emits no `role="option"` and no
  `role="listbox"`** (verified in `node_modules/react-select-5/dist/Select-db7a929e.cjs.dev.js:2500`).
  So `.actions-dropdown__option` / `.actions-dropdown-select__option` / `.team-dropdown__option` /
  `.label-filter-select__option` are all correct as written. Every DropdownWrapper site in the suite
  already uses the testid.
- **Hard evidence for the react-select-v5 trigger sanction.** With `isSearchable={false}` (all Fleet
  filter/role dropdowns) react-select renders `DummyInput`, styled
  `width:1px; opacity:0; left:-100px; transform:scale(.01)` (same file, ~line 599). It carries
  `role="combobox"` and `aria-label`, so it is usable for *assertions*, but it is not a viable click
  target — `.…__control` must stay the click handle. Same story for Fleet's `Radio`
  (`opacity:0; width:0; height:0`) and `Checkbox` (which *does* expose a clickable
  `<div role="checkbox" aria-label={name}>`).
- Third-party Ace editor internals (`.ace_content`, `textarea.ace_text-input`) appear at 7 sites and
  are fine — noted once, not itemised.
